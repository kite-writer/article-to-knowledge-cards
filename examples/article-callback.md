# 什么是回调函数

在 JavaScript 中，回调函数（callback）是指被当作参数传给另一个函数，并在某个时机被"调回来执行"的函数。它让一段代码能在特定事件发生后运行，是异步编程的基础。

看一个最简单的例子：数组的 sort 方法可以接收一个比较函数作为回调。当调用 arr.sort(fn) 时，fn 会在排序过程中被多次调用，用来决定元素谁前谁后。这种在调用期间同步执行的回调，叫同步回调。

回调更常见的场景是异步任务。比如读取文件：readFile('a.txt', (err, data) => {...})，第二个参数就是回调。readFile 先返回，文件读完后系统再调用这个回调，把错误或数据传进来。程序不需要停下来等文件，可以继续干别的事，这就是"非阻塞"。

异步回调让代码不用等待，但也带来一个著名的问题——回调地狱。当一个异步操作的结果要作为下一个异步操作的输入时，回调会层层嵌套，代码变成倒金字塔，难以阅读和维护：

```
doA((a) => {
  doB(a, (b) => {
    doC(b, (c) => {
      console.log(c);
    });
  });
});
```

为了摆脱回调地狱，JavaScript 社区逐步演进出了 Promise、async/await 等方案。Promise 把回调的嵌套改成链式调用 doA().then(doB).then(doC)，而 async/await 让异步代码读起来像同步代码。这些方案解决的都是同一个问题：让"后续处理逻辑"更容易组织。

理解回调函数的关键是记住两点：第一，回调只是"把行为当参数传递"，它本身没有魔法；第二，同步回调在调用方函数内部立即执行，异步回调则要等到某个事件发生后由运行时调用，两者的执行时机完全不同。
